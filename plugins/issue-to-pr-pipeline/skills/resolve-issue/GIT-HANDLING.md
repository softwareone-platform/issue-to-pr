# Git-handling note (self-scoped; no edits to the user's .gitignore)

Disclosed reference for `resolve-issue` (SKILL.md "Git-handling note"). Read when a step reasons about why the handoff artifacts are not committed.

P3 writes a `.claude/resolve/.gitignore` containing a single `*`, so every artifact in that directory — `state.md`, `fact-check.md`, `decisions.md`, `plan.md`, `timings.md`, and the transient `plan.baseline.md` — stays out of git automatically. This scopes the skill's **own** artifact directory; it never modifies the consumer repo's root `.gitignore` (that remains the team's to manage). `review-code-risk` reads `plan.md` from the working-tree disk; its committed-baseline precondition is about the fix and its tests, not the plan, so `plan.md` does not need to be committed — and committing it would pollute b-code-risk's `merge-base..HEAD` code diff and the PR. A gitignored file is still on disk and does not make the working tree "dirty" (git does not see it), so `review-code-risk`'s clean-tree precondition still holds. `review-plan-risk` (a-harden-plan) has a **separate** precondition — it wants a *git-tracked* baseline for auto-fix, which an untracked `plan.md` cannot satisfy — so a-harden-plan hands it a **baseline copy** (`plan.baseline.md`, snapshot write-once) and `review-plan-risk` uses restore-from-copy as its undo; this preserves the auto-fix plus independent verification without committing `plan.md`, and the orchestrator still only sequences (it does not apply or verify the plan fixes itself). A team that wants the design in the PR for context can commit `plan.md` explicitly — a preference, not the default.
